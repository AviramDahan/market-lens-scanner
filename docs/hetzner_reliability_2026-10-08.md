# Hetzner runtime reliability (2026-10-08)

This release changes paper-trading infrastructure and scan candidate supply, not entry gates, risk limits, or exits.

- A committed but unpushed portfolio update is retried on the next scheduled run. The host only pushes when `origin/main` is an ancestor of local `HEAD`; divergent histories still stop for manual reconciliation. A pending Telegram outbox is delivered only after the backup is current and the worker image matches deployed code. A receipt-only interrupted state is committed and backed up without resending.
- The Smart Universe source rotation widens for large requests (maximum 120 symbols per healthy sector before quality checks). Liquidity, volatility, market-cap and sector eligibility checks remain unchanged. The requested 175 fresh names is a target, not a reason to admit ineligible names. Watch/open-position carry-forward stays outside that target.
- The separate `MARKET_LENS_AGENT_TOTAL_SCAN_LIMIT=180` production cap still limits the combined basket. With 48 carry-forward names, only 132 fresh names are scanned even if 175 are available. The Agent log now reports the selected counts after this cap, rather than the pre-cap proposal. Raising the cap requires a timed production scan first.
- Upstream `MMC` is normalized to `MRSH`, the current Marsh symbol. Scanner-only candidates with a confirmed failure for fewer than 200 weekly bars after two focused recovery attempts are deferred for seven days and then retried; two separate failed runs also qualify. Open-position carry-forward is never suppressed. The 200-week requirement remains unchanged.
- The host sends a rate-limited operations alert when available disk falls below 12 GiB (`MARKET_LENS_MIN_FREE_GB` overrides this). No trading data is deleted automatically. The repository stores frequent XLSX snapshots, so Git history will continue growing. The separate daily structured-data archive protects historical records, but active-checkout retention still needs a separately verified design. Shared Docker cache is only pruned by the bounded maintenance procedure below; never run a broad Docker system prune on this host.

Verification: run `python -m pytest -q`, inspect `/health`, `/agent`, `/agent/data`, then confirm a new scanner record and monitor heartbeat on the host. A `PARTIAL_OK` record must list its missing tickers; it must not be reported as a complete scan. A successful no-event monitor proves evaluation only, not a live TP/SL touch.

## Shared host build-cache maintenance

The daily structured-data archive already runs in `AviramDahan/market-lens-data-archive` and does not include media. It is independent of Docker's local build cache. Do not use the archive as a reason to delete paper-trading records.

The host's default Docker builder is shared with AI Trader. `market-lens-build-cache.timer` checks it on Thursday at 23:00 and 23:15 UTC, after the regular session and between scheduled scans in both New York daylight and standard time. It skips if a Market Lens runner or any Docker build process is active. It runs only if cache reaches 30 GB or free disk falls below 20 GiB, and then prunes unused build-cache records last used at least seven days ago, targeting 16 GB with a 12 GB cache reserve. It never prunes images, containers, networks, volumes, Git history, or tracker data. Builds for either app may be slower after cache eviction. The second timer tick is a retry if the first was busy; an under-threshold check is harmless.

Inspect the result with `journalctl -u market-lens-build-cache.service` and `/home/trader/market-lens-runtime-state/maintenance/build-cache-last.json`. The operations Telegram receives `MAINTENANCE_FAILED`, `MAINTENANCE_INEFFECTIVE` if disk remains low after a no-op prune, or `DISK_LOW` under 12 GiB. The existing scanner disk warning remains in place. The target cache size is not guaranteed if the retained records are recent or shared with images; investigate rather than using `docker system prune -a --volumes`.
